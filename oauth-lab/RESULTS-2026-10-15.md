# 2026-10-15 FinAccess API7 연결 검증

화면은 FinAccess(18100)가 제공하고, USER API 호출은 API7(18090)의 `/oauth-access/api/user/me`를 거치도록 변경했습니다. Keycloak 로그인 주소·Client·redirect URI는 유지했습니다.

## 실제 등록한 설정

- Service `oauth-finaccess`: `host.docker.internal:18100`.
- Route `oauth-access-get`: GET·OPTIONS, 정확한 `/oauth-access/api/user/me` 경로.
- `openid-connect`로 JWT 검증 후 `acl`로 USER 검사. 같은 Bearer 토큰을 Spring으로 전달.
- `proxy-rewrite`로 `/oauth-access` 접두어 제거.
- `cors`로 18100 화면에서 GET·Authorization만 허용. OPTIONS는 Gateway가 직접 처리.
- Route `oauth-access-deny`: 나머지 경로·메서드 거절.
- 기존 FinAdmin 서비스·Route는 덮어쓰지 않았습니다. Spring의 기존 JWT·역할 검증도 유지했습니다.

## 이번 실행 결과

실제 Keycloak Code+PKCE·Device Grant로 LDAP USER/ADMIN 토큰을 발급했습니다. 아래는 이번 변경의 수동 HTTP 관찰 19건이며 JUnit 테스트 개수가 아닙니다. 실행 날짜가 다른 관찰 결과와 합산하지 않습니다.

| 확인 항목 | 예상 | 실제 | Spring 도달 |
|---|---|---|---|
| Gateway no token | 401 | 401 | 아니오 |
| Gateway malformed token | 401 | 401 | 아니오 |
| USER via API7 | 200 | 200 | finaccess |
| USER direct FinAccess | 200 | 200 | finaccess |
| USER to FinAdmin Gateway | 403 | 403 | 아니오 |
| USER direct FinAdmin | 403 | 403 | finadmin |
| Wrong HTTP method | 403 | 403 | 아니오 |
| Unknown access path | 403 | 403 | 아니오 |
| Tampered JWT Gateway | 401 | 401 | 아니오 |
| Tampered JWT FinAccess | 401 | 401 | finaccess |
| Allowed preflight | 200 | 200 | 아니오 |
| Foreign origin preflight | 200 | 200 | 아니오 |
| Expired JWT Gateway | 401 | 401 | 아니오 |
| Expired JWT FinAccess | 401 | 401 | finaccess |
| ADMIN to FinAccess Gateway | 403 | 403 | 아니오 |
| ADMIN direct FinAccess | 403 | 403 | finaccess |
| ADMIN FinAdmin Gateway regression | 200 | 200 | finadmin |
| ADMIN FinAdmin direct regression | 200 | 200 | finadmin |
| Forged USER header with ADMIN JWT | 403 | 403 | 아니오 |

- 브라우저에서도 USER 200·토큰 없음 401·ADMIN 403을 확인했습니다. 200은 Gateway와 FinAccess 헤더가 모두 있고, API7이 거절한 401·403에는 백엔드 헤더가 없습니다.
- CORS의 외부 Origin OPTIONS 200에는 허용 Origin 헤더가 없습니다. 브라우저의 교차 출처 허용이 성공했다는 뜻이 아닙니다.
- JWT 역할을 USER→ADMIN으로 바꾼 복사본은 서명이 유효하지 않아 401입니다. 별도로 정상 서명 토큰이 실제 exp를 지난 후 Gateway·Spring 401을 확인했습니다.
- Spring 직접 호출은 보안 필터 도달 여부를 보는 비교 경로입니다. 백엔드 헤더가 있다고 Controller 실행에 성공했다는 뜻은 아닙니다.
- FinAccess bootJar 빌드 성공 후 해당 JVM만 재시작했습니다. 새 테스트 소스·DB·중계 서버는 추가하지 않았습니다.

## 범위와 주의할 구분

- 실제 API7 제품 관리 API로 등록·조회하고 실제 데이터 요청으로 확인했습니다. 이번 작업에서도 관리 UI 클릭을 완료했다고 표현하지 않습니다.
- CORS는 브라우저 정책이며 인증·네트워크 접근 통제를 대신하지 않습니다. 직접 localhost 호출은 계속 가능하고 Spring이 별도 검증합니다.
- 운영 배포·SCIM·AI 모델 호출은 이번 변경 범위가 아닙니다.
