# 2026-10-14 로컬 실행 기록

> **10/14 실행 당시의 기록을 보존합니다.** 이후 USER API도 API7에 연결했습니다. 현재 구조와 추가 검증은 [10/15 결과](RESULTS-2026-10-15.md)를 참고하세요. 아래 결과를 이번 문서 정리 중 재실행한 것으로 표시하지 않습니다.

이번 `oauth-focus` 최소 구성에서 실제로 실행했습니다. 과거 금융·ITSM 테스트 숫자를 합산하지 않습니다. JUnit 테스트 소스는 추가하지 않았고, 실제 토큰 발급·curl·브라우저로 확인했습니다.

환경: Mac ARM64, Java 21, Spring Boot 4.1.1, Keycloak 26.7.4, Homebrew OpenLDAP 2.7.1, API7 Enterprise 3.10.2. Keycloak·LDAP·두 Spring은 로컬 프로세스, API7은 기존 Docker 설치입니다.

## 신원·부서 변경

- ldap-user 로그인: USER, Engineering. FinAccess 200, FinAdmin 403.
- ldap-admin 로그인: ADMIN, Operations. FinAccess 403, FinAdmin 200.
- LDAP ou를 Support로 변경 → 새 로그인 → API7 경유 응답의 department=Support.
- 변경 전 JWT는 같은 시점에도 Operations를 유지했습니다.
- LDAP ou를 Operations로 복원하고 새 토큰의 Operations를 확인했습니다.
- USER의 Payload 역할을 ADMIN으로 바꾼 토큰은 서명 실패로 세 경로 모두 401.
- 별도로 정상 서명 토큰을 수정하지 않고 exp가 지난 뒤 호출하여 만료 401 확인.

## 화면·CLI

- FinAccess 실제 브라우저: LDAP 계정 Code+PKCE 로그인 → USER API 200. 최종 응답에 subject·department·roles 표시.
- Keycloak 제품의 Device 화면: ldap-admin 로그인·승인 성공 → device_code로 토큰 교환 → curl로 API7 경유 FinAdmin 200.
- Device Grant에서 USER 토큰 발급도 확인. ID Token 없음.
- FinAdmin은 static HTML이 없는 API 앱입니다.
- API7 현재 설정을 관리 API로 다시 읽어 서비스와 Route 두 개 존재 확인. 기존 Route는 보존.
- `start-local.py`를 재실행해 이미 실행 중인 네 프로세스를 중복 기동하지 않는 것을 확인.

## 검증하지 않은 범위

이번 실행에서는 현재 API7 브라우저의 인증서 경고 이후 UI 조작을 완료하지 않았습니다. 제품 관리 API 등록·조회와 실제 Gateway 트래픽 결과를 UI 조작 완료로 표현하지 않습니다. UI에서 사용자가 직접 바꿀 대상과 복원 값은 RUNBOOK에 있습니다.

SCIM 프로비저닝, 서비스 계정 Client Credentials 실제 발급, OIDC ID Token 소비, 실제 AD, 운영 TLS/LDAPS, 장애·부하·Kubernetes, AI 모델 호출은 실행 완료 항목이 아닙니다. 500은 Spring의 의도적인 예외 응답이며 Gateway upstream 장애 시험과 다릅니다.

원본 안전한 관찰 기록은 로컬 `.local/manual-results.json`에 있습니다. 토큰·암호 원문은 이 문서에 없습니다.
