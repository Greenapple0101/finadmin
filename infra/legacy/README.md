# JWT를 처리하지 않는 모의 레거시 서버

이 폴더는 인증 기능을 추가하기 어려운 기존 업무 서버를 보여 주는 작은 실습입니다.
실제 금융 시스템과 연결하지 않고, 조회용 샘플 JSON만 돌려줍니다.

## 누가 무엇을 확인하나요?

| 구성 요소 | 책임 |
| --- | --- |
| Gateway | JWT의 서명·발급자·대상·시간 검사, 경로·메서드별 역할 검사, 신원 헤더 재작성 |
| 전용 Docker 네트워크 | 일반 프런트·다른 백엔드가 레거시에 직접 접근하는 경로 제한 |
| 이 모의 레거시 서버 | Gateway가 보낸 신원 헤더가 있는지 확인하고 샘플 데이터 반환 |

**신원 헤더의 존재 확인은 인증이나 RBAC가 아닙니다.** 직접 접근할 수 있는 사람은
`X-Finlab-Subject`와 `X-Finlab-Issuer`를 만들 수 있습니다. 따라서 Gateway를 우회하는
접근 경로를 차단해야 하며, Gateway는 클라이언트가 보낸 신원 헤더를 그대로 믿지 않고
검증한 JWT의 `sub`와 `iss`로 덮어써야 합니다. 관리자 경로의 역할 검사도 Gateway가 맡습니다.

Docker 호스트 관리자나 Docker 소켓에 접근할 수 있는 사람까지 격리하는 구성은 아닙니다.
운영 환경에서는 전용 네트워크 정책, Gateway와 레거시 사이의 전송 보호 및 서비스 신원 확인도
함께 설계해야 합니다. Python의 기본 HTTP 서버는 이 로컬 모의 실습용입니다.

## 제공하는 경로

| 내부 경로 | 메서드 | 응답 |
| --- | --- | --- |
| `/healthz` | GET | 준비 상태만 반환; 신원 정보 불필요 |
| `/api/reports` | GET | 샘플 보고서 목록; 신원 헤더 두 개 필요 |
| `/api/admin/summary` | GET | 샘플 관리자 통계; 신원 헤더 두 개 필요, 역할은 Gateway에서 검사 |

신원 헤더가 빠지거나 공백뿐이거나 같은 이름으로 중복되면 401을 반환합니다.
정의한 경로 외에는 404, POST·PUT·PATCH·DELETE 등 지원하지 않는 주요 메서드는 405입니다.
알 수 없는 확장 메서드는 Python HTTP 서버의 기본 거절 응답을 따릅니다.
모든 응답에는 `X-Finlab-Backend: legacy`를 넣습니다.
성공한 업무 조회 응답의 `sampleData: true`는 실제 업무 데이터가 아님을 나타냅니다.
이 서버는 Bearer 토큰을 사용하지 않으며 응답에 토큰을 포함하지 않습니다.

## 실행과 검증

Dockerfile은 내부 포트 8082에서 실행하고 `GET /healthz`로 준비 상태를 확인합니다.
Compose의 서비스에는 호스트에 공개하는 `ports` 설정을 넣지 않습니다.

저장소 루트에서 아래 명령으로 외부 서비스 없이 단위 테스트를 실행할 수 있습니다.

```sh
python3 -m unittest discover -s infra/legacy -p 'test_*.py' -v
```

테스트는 빈 임시 포트를 사용하므로 실행 중인 FinLab 서비스에 영향을 주지 않습니다.
단위 테스트는 이 서버의 입력·출력만 검증합니다. Gateway의 역할 검사, 외부 헤더 덮어쓰기,
레거시 직접 접근 차단은 전체 환경에서 별도로 검증해야 합니다.
